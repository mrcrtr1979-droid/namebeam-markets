Verify a row

Take a public answer file from the Namebeam record and the hash published for it, and check them yourself. Your browser computes the hash of the file and says MATCH or NO MATCH. The file is read on your device and is not sent anywhere.

The hash is SHA-256. The Edition 1 answers table lists one for each raw answer file. Edition 1 covers 2026-09-01 to 2026-10-13 and holds 12,180 dated rows.

Step one. Give the file

How will you give the file?

Upload is exact. The page hashes the bytes of the file as they are on your device.

Pasted text is hashed as written in the box, using the usual web text encoding. The browser turns Windows line breaks into plain line breaks, so a file saved with Windows line breaks can show NO MATCH when pasted and MATCH when uploaded.

The page fetches this one link from your browser, without cookies. The host must allow reads from other sites; raw.githubusercontent.com does.

Step two. Give the published hash

Paste the hash as the record prints it. A line from a hash list, such as the hash, two spaces and a file name, is accepted.

Do not have the hash? Look up a row

Give a link to a public list, or choose a downloaded list file; if both are given, the link is used. The page reads hash lists, CSV files with a hash column, and JSON.

In the answers table the row id is the source_file name. In the manifest it is the file path. The .json ending is optional.

What a result shows

A MATCH shows that your file has the same bytes as the file the hash was recorded for, so the file is unchanged since the hash was recorded.

A MATCH does not show that an engine gave that answer on that day, that the answer is correct, or that the list the hash came from is untouched. To check the list too, download the Edition one release and run its verify script against its manifest.

A NO MATCH shows that the two hashes differ. Check the file name, the row id and how the file was saved, then try again with the uploaded file.

Some rows in the record carry a hash, a count and flags and have no public answer file. This page looks those rows up and has no file to check them against.

How the page works

The page is one file. It loads no outside scripts, sets no cookies and keeps nothing after you close it. It makes a network request when you press Fetch the file or Look up, and that request goes to the link you typed. Uploaded and pasted files are not sent anywhere.

You can check the work with a tool you already trust. Command line, written 2026-11-24: sha256sum FILE on Linux, shasum -a 256 FILE on a Mac, certutil -hashfile FILE SHA256 on Windows.
