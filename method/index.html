Method

What a row is

For each question, on each run day, we send the same words to each source and log one row per source: the status, the names found in the answer, and the SHA-256 of the raw answer file. The sources are OpenAI, Anthropic, Perplexity and Gemini (by API) and Google search.

What the status words mean

Status words: OK means an answer was logged. QUOTA_BLOCKED means the engine refused the call over its quota. FAILED means the call did not complete. EXTRACTION_FAILED means the response came back without readable results (in the logged rows this is Google search pages blocked by a consent wall or captcha). Every status is printed at the same size as the wins.

Names and merging

Names are extracted from each answer. Spelling variants that the Edition 1 files group together are shown as one name. Dashes and curly quotes are normalized to plain characters in names. Extraction is automatic, so some entries are headings or terms and not businesses. We log that on the corrections page.

Two counting rules, and which page uses which

Extracted-list rule (the record pages on this site, the Edition 1 answers table, the per-market hashed files): a business counts for an engine on an answer day when it appears in the business list the collector extracted from that answer (bold names and listed names, each verbatim in the answer). Text-mention rule (the homepage explorer, data/explorer_data.json, the named lookup, and the market pages on namebeam.ai and on this site): a business counts for an engine on every answer day whose saved answer text names it, whole words, full name, punctuation ignored. The explorer, its data file and the market pages on both sites add one check: each word that the name writes with a capital letter must also start with a capital letter in the answer. The two rules give different numbers for the same business and window: for Chicago personal injury attorneys, OpenAI, one Chicago personal injury business counts on 18 of 39 answer days under the text-mention rule (Sep 1 to Oct 11, 2026) and on 4 of 71 answers under the extracted-list rule (Aug 9 to Oct 19, 2026). Every page states which rule it uses beside its numbers; never compare a count from one rule with a count from the other.

DQ-5, the extracted-list undercount. The name lists under-count the businesses an answer mentions, on every engine and by different amounts. For Anthropic the collector reads bold spans as names, so a plain-text mention is missed; for the other engines a name outside the list the engine wrote is missed. A recount of the 71 OpenAI answers for Chicago personal injury (Aug 9 to Oct 19, 2026) found one Chicago personal injury business in the text of 36 of 71 while the extracted lists named it on 4. This is documented in the Edition 1 pack README as DQ-5 and applies to every extracted-list count on these pages. The market pages were recounted under the text-mention rule and now use it (Corrections, 2026-10-21); the undercount above still applies to the record pages and the Edition 1 files, which count extracted lists.

Units, so numbers are not mixed

47 questions: the September 2026 roster, asked on each of 30 days. 73 questions: the Edition 1 roster, Sep 1 to Oct 13, 2026 (55 market or category questions and 18 named-business probes), 42 run days, 12,180 answer rows. 46 market cells: the slice of the explorer file behind the Digital Information World study, a market plus a niche, Sep 1 to Oct 11, 2026, 24 markets and 33 niches. The live explorer file (data/explorer_data.json, read 2026-10-24) holds 52 cells, 24 markets and 34 niches over Aug 5 to Oct 21, 2026, and grows with each run day. 27 market pages: one question each, from Aug 5, Aug 9 or Aug 26, 2026 by market; each page states its window. Edition 1 ends 2026-10-13; Gemini answered only on 2026-10-15 and 2026-10-16 after it. A run day is a date with at least one row; an answer day for an engine is a date with an OK row from that engine.

Who entered and who dropped

Each run day is compared with the previous run day that has rows. The engines that answered OK on both days are the ones compared, so an engine skipping a day cannot look like a business dropping out.

What the counts are not

A count is not an order of businesses, not a score and not a promise about traffic or bookings. AI answers vary from run to run.

Check it yourself

Each CSV lists the raw file name and its SHA-256. The raw files are in the public corpus. manifest.sha256 lists the hash of every CSV on these pages.

How the record is made

Questions

We ask OpenAI, Anthropic, Gemini and Perplexity through their APIs and collect Google result pages. Perplexity uses web search. The other APIs run without a search tool.

Edition 1 lists 73 distinct questions in data/prompts.csv: 53 shared by four engines and 20 specific to Perplexity. On 2026-10-08 the daily record has 53 question rows per source, with 73 for Perplexity. From 2026-10-30 through 2026-11-24 it has 73 per source, with 93 for Perplexity. Question coverage varies by source and date. Read prompt_text in each dated file for its wording. Variant 2 uses separate wording and files in corpus/e1_q2. Coverage can be incomplete.

Naming

As of 2026-11-24 the record and Edition 1 tables count names in the collector's extracted list. The explorer and market pages count full names in saved text using whole words, ignoring punctuation and checking capitalization. Automatic lists can include headings and miss plain-text mentions.

Limits and verification

A daily answer is one sample. This page gives no sampling interval. API answers can differ from consumer apps. Counts describe this collection. User volume, business outcomes and causal effects require other evidence.

Download the raw file named in the CSV row and compare its SHA-256 with the listed hash. Follow the verify-one-row recipe below (checked 2026-11-24).

Verify one row of the record

Use a POSIX shell with curl, grep, sed, tr and GNU sha256sum. Run in an empty directory. The examples use saved public files read on 2026-11-24. Downloads come from the public repository and record pages.

Edition 1 example

This is the OpenAI market row dated 2026-09-10. Download the raw file, the original answers table, the manifest and the question roster.

R=https://raw.githubusercontent.com/mrcrtr1979-droid/namebeam-visibility-index/main
F=NB-CZ-API_2026-09-10_segment_hvac_atlanta_openai.json
A=answers_2026-09-01_to_2026-10-13.csv
H=747d93419030d26415d354d8955026f8646ffd6c487234af4e13477bc357c58c
curl -fsSLo "$F" "$R/corpus/e1/$F"
curl -fsSLo "$A" "$R/releases/edition-1/data/$A"
curl -fsSLo MANIFEST.sha256 "$R/releases/edition-1/MANIFEST.sha256"
curl -fsSLo prompts.csv "$R/releases/edition-1/data/prompts.csv"
sha256sum "$F"
grep -F "$F" "$A" | grep -Fc "$H"
grep -F "$F" "$A" | grep -F "$H" | sed 's/^\(2026-09-10,API\).*/\1/'
grep -F "data/$A" MANIFEST.sha256 | sed 's#data/##' | sha256sum -c -

Expected for the 2026-11-24 snapshot: the raw hash equals H. The row count is 1 and the prefix is 2026-09-10,API. The manifest check prints answers_2026-09-01_to_2026-10-13.csv: OK for SHA-256 398f7cc5f76a3060eba318d0231e4b32f92a3155064debb0bc68f0c9fb499f03.

Check the wording and status for this example. For other raw files, decode prompt_text as JSON before hashing if it contains escapes.

grep '"prompt_text"' "$F" | sed 's/^ *"prompt_text": "//; s/",\{0,1\}$//' | tr -d '\n' | sha256sum
grep '^segment_hvac_atlanta,' prompts.csv | grep -o '[0-9a-f]\{64\}'
grep -E '^[[:space:]]*"(date_utc|engine|run|run_status)"[[:space:]]*:' "$F"

Expected for the 2026-11-24 snapshot: both wording hashes equal e5c643a5a8786df6fd9622088822feb9627a801eb1947153b5e8565b618f0e13. The status fields show 2026-09-10, openai, run 1 and OK. For status across Edition 1 use the answers table with the _run_status suffix. A failed call or unusable extraction is missing usable data.

Optional whole-pack check: from the complete repository checkout, run python3 releases/edition-1/verify.py. The 2026-11-24 manifest lists 33 files. The verifier reports VERIFY MATCH when the pack agrees.

What the match establishes

A match establishes byte agreement with the checked table and manifest. The wording check establishes agreement with the published prompt for this example. Engine attribution comes from the collection record. These checks establish neither independent engine provenance nor the accuracy of the extraction or aggregate counts. From 2026-10-25 the public Perplexity and Google AI Overview records can support checks of published fields, with the withheld text unavailable for a public recount.
